# 01_basic

> English: [README.md](README.md)

既定設定で名前付きフックを開始するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [01_basic.ino](01_basic.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<ESP32AutoTask.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `ESP32AutoTask::AutoTask.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。

## APIの使い方と注意点

シリアルや周辺機器を準備してから `AutoTask.begin()` を呼び、例と同じ名前のグローバルなフック関数を実装します。フックはArduinoのloopとは別のタスクで動きます。static変数は状態を保持しますが、共有データには別途同期が必要です。

単一コアではCore1名のフックも利用可能なコアへ割り当てられるので、名前だけで並列実行を判断しません。`periodMs` は予定する間隔で、締切保証ではありません。処理が長すぎれば指定周期には追い付きません。

ESP32のスタック設定はbyte単位です。必要な設定だけ変え、全設定例を将来も不変の既定値一覧として扱わないようにします。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
[Core1 Normal] millis=%lu
```

## 確認と問題の切り分け

既定設定で名前付きフックを開始することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
